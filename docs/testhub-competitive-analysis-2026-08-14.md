# TestHub 竞品分析 & 对我方 agent-eval 平台升级的借鉴（2026-08-14）

> 来源：5 篇微信公众号文章（TestHub 6.0 / 6.1 / 7.0 / 测试计划生成 / UI 录制 Vibe Coding）
> 结论先行：**TestHub 是「用 AI 提效传统测试」的平台，与我方「测 Agent/LLM 本身」的 agent-eval 主舱是不同赛道**。不能直接对标我们的评测能力，但它在「AI 体验壳 + 知识中枢 + Skills 生态 + 调度流水线」上验证了多个可迁移的产品模式。

---

## 1. TestHub 到底是什么

- **定位**：传统测试自动化平台（UI / API / APP / 性能），AI 作为「提效层」叠加。
- **形态**：闭源「星球版」（付费）+ 开源基础版。
- **AI 角色 = copilot / 调度器（Hermes 质量数字人）**，负责写用例、跑测试、创计划、造数据、查知识库。
- **关键模块**（从 5 篇文章提取）：
  1. **Hermes 调度中枢**：一句话 → 驱动各模块（接口/UI/APP/知识库），可绑飞书远程下达任务。
  2. **知识中枢（RAG）**：「同一份知识既被人读、又被 Agent 检索」；可插拔知识源（Confluence/飞书/Notion via MCP/API）；MinerU/TextIn 解析 → Qwen3-Embedding-8B + bge-reranker-v2-m3 精排 → 辅助用例生成。
  3. **Skills 生态**：VIP 仓库 45+ 测试 Skill（需求分析/用例生成/用例评审/缺陷管理/接口/性能/报告/测试计划…），用户可导入 zip 技能。
  4. **test-plan-designer Skill**：自然语言 → 10 章测试计划（目标/范围/不测范围/策略/类型/环境/数据/依赖/风险矩阵/准入准出）。
  5. **UI 录制回放**：Playwright Codegen 录制 → 脚本回放；视频执行回放。
  6. **性能模块**：JMeter + InfluxDB 时序库 + ECharts 实时看板（在线编排 / JMX 导入）。
  7. **飞书/企微/钉钉打通 + 定时任务 + 多通知**：自动化巡检流水线。
  8. **MVP 优先哲学**：「完成比完美重要」，先跑通再迭代（UI 录制用豆包模型 30 分钟出 MVP）。

## 2. 核心差异（关键，避免误把竞品当对标）

| 维度 | TestHub | aotutest agent-eval |
|---|---|---|
| **被测对象** | 软件系统（UI/API/APP/性能） | **AI Agent / LLM 本身** |
| **AI 的角色** | 写用例/跑测试的 copilot | **被测对象 + judge（裁判）** |
| **核心指标** | 通过率 / 覆盖率 / 性能 TPS | **Pass@k / 忠实度 / 工具准确率 / 红队 / Elo 榜单 / 基线回归** |
| **我方有它无** | — | Pass@k、faithfulness(D1)、死循环/幻觉红线、红队 REDTEAM、LLM-as-Judge+复核门(M3)、PoLL 多裁判、Elo 榜单(A4)、数据集版本化+Diff(A3)、数据不出域(A2) |
| **它有我方无** | 传统自动化全栈、知识中枢、Skills 市场、飞书/企微、UI 录屏 | — |

**结论**：TestHub 的「主舱」正是我们定位里的「辅舱」（传统自动化退居辅舱）；我们的「主舱」(agent 测评) 它完全没有。→ **该借鉴它的「壳」，不要抄它的「舱」。**

## 3. 对我们有帮助的 7 个可迁移点（按价值排序）

| # | 借鉴点 | TestHub 做法 | 我方映射 | 价值 |
|---|---|---|---|---|
| 1 | **知识中枢 / RAG 上下文** | 需求文档/Confluence/飞书 作为 RAG 上下文辅助用例生成 | 增强 **B1 用例生成 Agent**（当前为离线启发式，无外部上下文） | 高（新能力，提质） |
| 2 | **调度中枢 / Copilot 对话入口** | Hermes 一句话路由到各测试模块 | 强化 **A1 前端 + B1/B3**：自然语言 → 生成评测计划/跑数据集/看门禁 | 高（体验壳） |
| 3 | **eval-plan-designer Skill** | 自然语言 → 10 章测试计划 | 新增「评测方案生成」：从需求自动选数据集+指标+门禁（**我方缺失，差异化强**） | 高 |
| 4 | **Skills 生态（导入/版本化）** | 用户可导入 zip 技能，45+ 技能市场 | 验证 Eval-Anything「Skill-as-versioned-evaluator」：把**评分器做成可导入版本化 skill** | 中高 |
| 5 | **性能/成本维度 + 实时指标流** | JMeter+InfluxDB 实时 TPS/响应/错误率 | agent 评测的 **latency / token-cost / throughput** 维度（P3 成本项）+ InfluxDB 式实时看板 | 中 |
| 6 | **执行回放 / Trace replay** | UI 执行视频回放 | 失败 eval case 的 **agent 工具调用过程可视化回放**（增强 M4 Trace） | 中 |
| 7 | **定时评测 + IM 通知** | 定时任务 + 飞书/企微/钉钉 通知 | **周期性评测流水线 + 结果推送**（增强 C3 CI 门禁，易做） | 低中（易落地） |

---

## 4. 不建议抄的（保持专注）

- **不要变成传统 UI/API/APP 自动化平台**：那是 TestHub 主舱、我们辅舱，赛道拥挤且偏离「agent 测评全栈」定位（与用户既定路线三一致）。
- **录屏/Codegen 录制**：对 agent-eval 价值有限；仅当要做 **agentic browser 基准（WebArena/OSWorld，已在 E7）** 时，可采集真人轨迹作 gold 数据源。

---

## 5. 建议补进 P3 路线图的条目

- **P3-2 知识中枢 RAG 上下文**（B1 用例生成增强）— 中
- **P3-x Copilot 对话入口 + eval-plan-designer**（差异化，我方缺）— 高
- **P3-3 Agent-as-Judge + 置信度门**（已排，前轮未动手）— 高
- **P3-y 成本/性能维度 + 实时看板**（接 P3 成本项，强化 M4/M5）— 中
- **P3-z 定时评测 + IM 通知**（增强 C3，易做）— 低中
- **P3-w 失败 case Trace 回放**（增强 M4）— 中

> 原则不变：**补缺不重造**。TestHub 验证的是「平台外壳与运营体验」，我们的护城河仍在 eval 核心指标（Pass@k / 忠实度 / 红队 / 榜单 / 数据不出域），这些它都没有。
